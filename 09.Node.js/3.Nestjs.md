# Nestjs基础知识

## 一、Nestjs CLi常用命令

### 1.创建项目

```
nest new project-name
```

生成一个新的 Nest 项目，默认会问你要用 **npm** 还是 **yarn** 安装依赖



### 2. **生成文件 (generate / g)**

这是你最常用的命令，`nest g` 是 `nest generate` 的缩写。

常见类型：

```
nest g module user        # 生成 user.module.ts
nest g controller user    # 生成 user.controller.ts
nest g service user       # 生成 user.service.ts
nest g class user/dto     # 生成 user/dto.class.ts
nest g interface user     # 生成 user.interface.ts
nest g filter http        # 生成异常过滤器
nest g guard auth         # 生成守卫
nest g interceptor log    # 生成拦截器
nest g middleware logger  # 生成中间件
```



### 3.**参数选项解释**

```
nest g service user --no-spec -d
```

**`g`**: generate（生成）

**`service`**: 要生成的类型，这里是 `Service` 文件

**`user`**: 生成的名字 → `user.service.ts`

**`--no-spec`**: 不生成测试文件（`user.service.spec.ts`）

**`-d` / `--dry-run`**: 只显示会生成什么文件，不实际生成（干跑一遍，常用来预览）



### 4.**运行/调试**

```
npm run start           # 启动项目
npm run start:dev       # 启动并监听文件变化，自动重启
npm run start:prod      # 生产模式
```



### 5.**构建**

```
npm run build
```

把 TS 编译成 JS，产物放在 `dist/` 目录。



### 6. **测试**

```
npm run test       # 运行单元测试
npm run test:e2e   # 运行 e2e 测试
npm run test:cov   # 查看测试覆盖率
```



### 7.**其它辅助**

```
nest info    # 查看 Nest 项目依赖环境信息
nest update  # 升级 Nest 相关依赖
```



### 总结

- `nest new` → 新项目
- `nest g ...` → 各种文件
- `npm run start:dev` → 启动开发
- `npm run build` → 打包
- `nest info` → 查看环境

## 三、**模块**



  在 **NestJS** 中，模块（Module）是构建应用的基本单元，它是组织相关功能的容器，每个模块通常包含服务、控制器、提供者等。一个模块有四个核心属性。



### 1.**`imports`** - 导入其他模块

- **功能**：`imports` 数组用于导入其他模块，使得当前模块可以访问到被导入模块的功能（例如，控制器、服务等）。

- **应用场景**：通过 `imports`，模块之间可以共享功能。例如，A 模块需要使用 B 模块提供的服务，则需要在 A 模块的 `imports` 中引入 B 模块。

  ```tsx
  @Module({
    imports: [BModule], // A模块可以使用B模块的功能
  })
  export class AModule {}
  ```

  

### 2.**`controllers`** - 控制器

- **功能**：`controllers` 数组定义了与请求相关的处理逻辑。控制器主要处理传入的 HTTP 请求，并返回响应。每个控制器都是由一个或多个路由处理函数组成。
- **应用场景**：控制器通常通过装饰器（如 `@Get()`, `@Post()`）来定义请求的路由规则和处理逻辑。

```tsx
@Module({
  controllers: [AController], // 注册AController
})
export class AModule {}
```



### 3.**`providers`** - 提供者

- **功能**：`providers` 数组包含了服务、工厂、值等，它们通常用于依赖注入。NestJS 会根据模块的依赖关系来自动注入所需的服务或提供者。
- **应用场景**：服务通常通过 `@Injectable()` 装饰器标记为提供者，然后可以通过依赖注入机制被其他类（如控制器或服务）使用。

```tsx
@Module({
  providers: [AService], // 注册AService作为提供者
})
export class AModule {}
```



### 4.**`exports`** - 导出

- **功能**：`exports` 数组用于将模块中的提供者（如服务）暴露给其他模块使用。只有被 `exports` 导出的提供者才能在其他模块中通过依赖注入进行访问。
- **应用场景**：如果一个模块中的某个服务需要供其他模块使用，就需要将该服务添加到 `exports` 中。

```tsx
@Module({
  providers: [AService],  // 定义AService作为提供者
  exports: [AService],    // 导出AService供其他模块使用
})
export class AModule {}
```



### 总结

NestJS 模块的四大属性分别是：

1. **`imports`**：导入其他模块。
2. **`controllers`**：控制器（处理请求）。
3. **`providers`**：提供者（服务等，支持依赖注入）。
4. **`exports`**：导出提供者供其他模块使用。

这些属性帮助 NestJS 组织、管理和共享应用程序的功能，使得模块化开发和依赖注入得以高效实现。



# TypeOrm的使用

## 一、TypeORM 基础概念

  **TypeORM 是一个用于 Node.js 的“对象关系映射”库，它的主要作用是让开发者能够用面向对象的方式（比如使用 TypeScript 或 JavaScript 的类）来操作关系型数据库（如 MySQL、PostgreSQL、SQLite 等），而无需直接编写复杂的 SQL 语句。**

用一个简单的比喻来理解：

想象一下，你有一个 Excel 表格（数据库），里面有一张“用户表”，有“姓名”、“年龄”等列。

- **没有 TypeORM 的情况**：你每次要新增、查询、修改数据，都需要手动打开 Excel，找到对应的表格，写一些复杂的公式（SQL 语句）来操作。这很繁琐，而且容易出错，尤其是当表格关系很复杂的时候。
- **有 TypeORM 的情况**：你不再直接操作 Excel 表格。相反，你定义了一个“用户模板”（TypeScript 类），然后你只需要对这个“模板”的实例（对象）进行操作。TypeORM 就像一个超级助手，它会自动帮你把对对象的操作（比如 `user.save()`）翻译成对 Excel 表格的操作（`INSERT INTO users ...`）。

**简单来说，TypeORM 在你写的代码和数据库之间充当了一个“翻译官”或“桥梁”的角色。**
